# 拼豆图纸转换器 · P1-A 抠图服务

`需求.md` E5（Story 5.1 自动抠图）的后端实现，对应技术方案 §3.2 的 **P1-A** 模块。

## 为什么抠图是唯一上后端的环节

技术方案 §0.5.5 的结论：整条转换链路里，**只有抠图是「模型/算法确实更强」的问题**。

| 问题 | 本质 | 前端能不能做 |
|---|---|---|
| 抠图（主体边缘、背景扣除） | 语义分割 / 区域增长 | ❌ 纯前端只能做边界洪水填充，复杂背景必挂 |
| 背景花成色斑 | 量化误差放大 | ✅ 已在前端解决（平坦区统一，§2.8） |
| 每格该用哪个色号 | 量化 + 空间一致性 | ✅ 前端；且精度已被**色卡密度**锁死（§0.5.4） |

因此本服务**只做抠图**。解码、裁剪、重采样、主色提取、量化、渲染、导出全部留在前端——
它们都是毫秒级的纯数组运算，上后端只会增加往返和隐私风险（§0.5.6 的红线）。
**P0 的验收基线不依赖任何网络请求**，抠图服务不可用时前端其余功能完全正常。

## 引擎链路（v1.6）

边界洪水之后新增**平坦区吸收**：量化 Lab 连通域中「面积 ≥10%、与已扣区相邻、不含前景
种子中心框」的色区并入背景种子。解决插画类素材的实测失效——背景（黄底 51.7%）被一圈
细奶油边框与画幅边缘隔开，单一背景色的边界洪水在边框处停止，黄底整体被当前景
（蒙版保留 91.8%、对齐率 40.2%）。吸收后六张老素材前景占比**逐比特不变**（零回归），
人像插画对齐率 → 89~91%。

> ⚠️ 同时修正的前端契约：前端发给后端的是**完整原图**（不是工作区裁剪块）——
> 裁剪块会把图片自身的细边框切掉，导致边界环混入两种颜色、单一背景色洪水失效
> （实测同图：全图蒙版 38.1%，裁剪块蒙版 100%）。返回的蒙版由前端按工作区
> 矩形裁剪后锚定，契约不变（需求 §2.5.3）。

## 启动

```bash
cd backend
python3 -m pip install -r requirements.txt
python3 app.py                 # 默认 127.0.0.1:8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 即可。

- 换端口：`python3 app.py --port 9000`，并在前端页面里设 `window.MARD_CUTOUT = "http://127.0.0.1:9000"`。
- 前端默认连 `http://127.0.0.1:8000`；连不上时会弹出启动指引，不影响裁剪/包边/改色/导出。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回引擎与确定性标记 |
| POST | `/cutout` | 图片进、蒙版出。返回与原图同尺寸的 8 位灰度 PNG（255 = 主体，0 = 背景，中间灰 = soft 边缘） |
| POST | `/matting` | 可选二次精修：在主体边带内用引导滤波收边 |

`/cutout` 的 form 参数：`long_edge`(1024) / `border_ratio`(0.02) / `fg_ratio`(0.10) /
`bg_delta`(5.0) / `feather`(1) / `keep_largest`(true) / `preview`(false)。
`preview=true` 时返回「蒙版叠在棋盘格上」的彩色图，用于人工目视检查。

## ★ 确定性是硬契约（不要退回 grabCut）

技术方案 §0.5.5 选用确定性 CV 而非生成式模型的**首要理由**就是：

> 同样的图 + 同样的参数 → 同样的蒙版 → 同样的图纸，可回归测试。

**`cv2.grabCut` 不满足这一条。** 实测（已刻在 `cutout.py` 顶部注释里）：即使使用
`GC_INIT_WITH_MASK` 显式播种，同一张图、同一份初始蒙版连跑三次，前景占比分别是
`62.855% / 62.816% / 63.116%`，蒙版哈希三次全不同——内部 GMM 参数估计在多线程下累加顺序
不定，浮点抖动被迭代放大。

现用引擎是完全确定性的替代链路，全部是整数或固定顺序浮点运算：

1. **背景色统计** —— 四边内侧像素的 Lab 中位数（抗离群）
2. **边界连通洪水** —— 扣掉「与画幅边界连通」且「与背景色差 < `bg_delta`」的像素
   （只用色差会把主体内部同色部分误扣；只用连通性会漏掉背景杂色；两个条件同时成立才判背景）
3. **分水岭精修** —— 以「确定背景」为种子沿源图梯度生长，自然停在主体真实轮廓
   （优先级队列按「灰度值 + 插入序号」全序排序，无随机源）
4. **最大连通域 + 孔洞填充 + 形态学清理**
5. **羽化出 soft alpha**

一处易踩的坑：分水岭的 `-1` 边界标签**不能一律归给背景**。`bg_seed` 覆盖最外圈时，
它自己那条外轮廓线也是 `-1`，一律归背景会让背景吃掉最外一圈像素。正确做法是
`-1` 只在「本来就被判为 outside 的位置」才归背景。

cd backend && python3 test_cutout.py

## 隐私

图片只在内存中处理，请求结束即释放；**不落盘、不记录、不上传第三方**。
上限：单文件 40MB、解码后 5000 万像素（防内存炸弹）。
